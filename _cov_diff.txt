+The **TritonBench-G column is empty for every budget-matched row**, ours
+included. The cause is a property of that corpus, verified file by file:
+each task ships a Triton kernel together with the test function that
+exercises it, and the reference values against which its published
+evaluation compares are produced by *the file under test itself*. The
+corpus therefore supplies no independent reference implementation, and
+contract-based differential validation—for B1u, B7, B8, B9, B11, M-full,
+and M-dir alike—has nothing to compare against until references are
+authored separately. The absence is uniform across rows, so it cannot bias
+the comparison among them; what it does bound is external validity, which
+rests on the CUDA corpora until the column is filled. Our remediation is
+fixed in advance: we author PyTorch references for a *pre-registered
+uniform random subsample* of the 184 tasks under a recorded seed, and the
+filled column will be reported on that subsample with its sampling design
+and inclusion probabilities declared, so that the same Horvitz–Thompson
+and Hájek estimators used for the all-PASS audit stratum (Section 5.1.5)
+carry the subsample to a population statement. A reference that disagrees
+with the corpus's own recorded values is adjudicated manually, and a
+disagreement traced to the kernel rather than to our reference is itself
+recorded as a finding; agreement is treated as a smoke check and never as
+evidence that the reference is correct.
