## 协议杠杆启用记录：early-stop-on-fail（2026-08-02 23:04）

**触发数据**（点火后 ~4 小时实测，观测 217 条时决策）：每 case 中位
56.5 s / 均值 57.7 s——编译产物核对显示 161 条 C3 观测对应 134 次真实
nvcc 编译（缓存键为 科目×策略，同内核最多被 6 个策略各重编一次），当前
轮转调度处于"编译前沿"，GPU 大面积空转；直线外推全战役 60+ 天，摊销后
预估仍需 15–20 天，超出点火预估窗口。

**决定**：启用 runner 预注册参数 `--early-stop-on-fail`（语义：某
(科目×策略) 出现首个 fail 后跳过其后续 case，计入 `skipped_after_fail`；
`detected_pairs` 于启动时从账本重建，续跑感知）。该参数属部署语义
（deploy 模式首违规即停），不改判定协议、不改预算口径；受影响行的
"32 调用预算"如实降级为"至多 32 调用、首告警截断"，与 §5.7 deploy 模式
口径一致，聚合脚本按 planned/observed 两列区分。

**执行与溯源**：
- `guard_lane_m.sh` v2（加 `--early-stop-on-fail`；完工判定由固定观测数
  改为 runner 终局 summary JSON 检测）提交至 provenance commit
  `b298ac1f`（内联身份 mk-ops，worktree clean）；
- 环境清单 v2：`wave1_environment_v2.json`（capture_sha256 `f3827248…`，
  含 nvcc 指纹——首次采集因缺 CUDA PATH 与 runner 环境不一致被拒启，
  带 `PATH=/usr/local/cuda/bin` 重采后通过）；
- run_manifest 严格校验不允许同目录换配置，原 manifest 原地归档为
  `run_manifest_v1_pre_earlystop.json`（1.7 MB，未改动），runner 于
  23:04 生成 v2 manifest（`early_stop_on_fail: true`）并从同一
  append-only 账本按 test_id 精确续跑；每条观测自带
  run_manifest_sha256，两阶段可逐行区分；
- 切换期间脏树窗口内 runner 全部正确拒启、零观测写入（账本 217→220 的
  增量全部来自切换后的 v2 阶段与切换前的 v1 正常运行）。

**预期效果**：fail 密集科目（当前 36% case fail）的后续 case 被截断，
结合编译摊销，全战役 ETA 回落；24 小时后复查吞吐，若仍超窗启用备选
杠杆（plan 重排为同科目连排以摊销编译）。
