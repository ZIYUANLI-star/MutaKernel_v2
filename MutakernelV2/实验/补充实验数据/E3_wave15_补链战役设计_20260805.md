## 2. 三条预注册复用规则（分析层复用，账本永不伪造）

**R1 oracle 单调性结转（Lane G）**。legacy oracle（平坦 atol=rtol=1e-2，无 dtype
表）在每个 dtype 上都不比统一 oracle 更严：fp32 由 1e-4 放宽到 1e-2，fp16/bf16
两侧同为 1e-2，其余 oracle 布尔开关逐字节相同。因此统一 oracle 下的 PASS 在
legacy 下必为 PASS；崩溃/INCONCLUSIVE 与容差无关，原样结转。唯一可能翻转的是
FAIL 案例——Lane G 只对"anchor 行或 mutakernel-full 行出现过至少一次 FAIL 的科目"
重跑完整两行（legacy 契约变体清单，early-stop 生效），其余科目的 legacy 行结论
在聚合层以 `oracle-monotonic-carryover` 标签结转，不产生伪造账本记录。

**R2 保留 case 结果复用（Lane L-a）**。对 M-full 行零 FAIL 的科目，其全部 31 个
case 都已在 Lane M 真实执行（early-stop 未截断），LODO −X 行的"保留部分"结果
完整可复用；Lane L-a 只执行"重分配补充 case"（delta 行）。聚合时 LODO −X 的科目
级检出 = 保留部分（Lane M 账本）∪ 补充部分（Lane L-a 账本）的任一 FAIL。

**R3 已检出科目全行重跑（Lane L-b）**。对 M-full 行有 FAIL 的科目，Lane M 的
early-stop 截断了保留 case 的执行，复用不完整；Lane L-b 对这些科目重跑完整
LODO full 行（保留 case 在前、补充 case 在后，early-stop 使多数科目在首个保留
FAIL 处快速截断，成本可控）。

三条规则的共同前提是执行确定性（bit-exact 生成器测试在案）与环境一致性（同一
GPU、同一 torch 栈；环境清单 v3 与 v2 仅 git commit 前进、依赖指纹一致，差异
记录在 S1 冻结步）。规则连同数据一起随 artifact 披露。

## 3. LODO 五行的维度划分与重分配规则（Table 11）

M-full 的 31 个 case（成本 32）按五维度精确划分：

| 维度 | case | 成本 |
|---|---|---|
| 值（value） | 21 个默认参数 eval 应力策略 case | 21 |
| dtype | iid fp16、iid bf16 | 2 |
| 训练（train） | near_zero/train、uniform_constant/train | 2 |
| 重复（repeat） | iid repeated(repeat_count=2) | 2 |
| 配置（config） | iid batch 1/4/16/64 + iid layout noncontiguous | 5 |

**重分配规则（retained-cycle-seed-increment）**：LODO −X 行删除维度 X 的全部
case，释放的预算按"保留 case 列表按声明顺序循环、seed 取 100000×cycle+原seed"
确定性补足，直至预算恰好用尽（cost-2 的 repeated case 在剩余预算不足时按序跳过）。
delta 行（仅补充 case）与 full 行（保留+补充）中的补充 case 逐字段相同，保证
跨行合并一致。五行计划均通过 `validate_frozen_plan` 语义校验。
